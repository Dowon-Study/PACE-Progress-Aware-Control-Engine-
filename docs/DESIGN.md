## 0. 요약

**AI가 느리든, 끊기든, 틀리든 로봇은 물리적으로 멈춰야 할 때만 멈춘다.**

이 플랫폼은 AI 추론 계층이 내는 액션 청크(경로)를 1kHz 실시간 제어 계층이 **시간이 아니라 "로봇이 실제로 어디까지 왔는가(진행도)"를 기준으로 이어 붙이고**, 청크가 늦을 조짐이면 미리 느려지고, 끊기면 로컬 연속 정책이 선을 이어 그리며, 정지는 로봇 상태를 보는 규칙만이 결정한다. 시연 과제는 용접선 추종이다. 용접에서는 멈추면 불량이므로 "멈추지 않고 버티는 길이"가 플랫폼의 성능 지표가 된다.

모든 주장은 MuJoCo 락스텝 시뮬레이터 위의 실제 1kHz 루프에서 실측했다.

| 과제가 요구한 것 | 이 플랫폼의 실측값 |
|---|---|
| 제어주기 1ms, 지터 ±100μs | 실제 루프 깨어남 지연 유휴 max 16.7μs / 부하 41.8μs (일반 커널 592/1325μs) |
| AI 출력의 범위·유효성·시간 검증 | 3단계 검증기, 장애 주입 7종 전부 의도한 단계에서 거부 |
| 지연·중단 시 급격한 동작 방지 | 정지 0회 공급 중단 길이: 유지 2s → 페이싱+외삽 4s → 로컬 정책 ≥10s (허용 오차 1mm 안에서 6s) |
| 제조사 비종속 HAL | UR5e·Panda·iiwa14·xArm7·ros2_control 플러그인 경로 모두 같은 제어기로 용접 오차 0.29~0.32mm |
| 예외처리 시연 | 폴트 → 아크 OFF → 0.4s 감속 → 유지 → 2s 뒤 비상정지 체결, 네 로봇 동일 타임라인 |
| 비전 기반 보정 | 작은 눈(고전 CV)으로 고정구 오차 1.47mm → 0.29mm |
| 센서 기반 접촉력·속도 조정 | 돌출부 접촉 53N → 0.5× 감속 + 스탠드오프 +26mm, 완주 |
| 공정 상태 기반 파라미터 변경 | 페이싱 구간에서 아크 출력 100→30%, 입열 지수 최대 1.7 (제어 없으면 5.0) |
| AI 부하별 제어 성능 | 6조건에서 루프 실행 p99 7μs 불변 |

## 1. 문제 정의

학습 기반 로봇 정책(ACT, VLA 등)은 수 Hz~수십 Hz 로 수백 ms 길이의 액션 청크를 낸다. 이것을 1kHz 서보 제어와 묶을 때 두 가지 문제가 생긴다.

1. **판단의 시간 불일치.** 추론 중에도 로봇은 움직인다. 청크가 도착했을 때 로봇은 청크가 가정한 자리에 없다. 시간 인덱스로 재생하면 접합 순간에 튀고, 지연이 커지면 과거를 추종한다.
2. **공백.** 추론이 늦거나 통신이 끊기면 참조가 바닥난다. 멈추면 안전하지만 용접처럼 "멈춤 = 불량"인 공정에서는 멈춤 자체가 실패다.

여기에 과제가 요구하는 제약이 더해진다. 실시간 계층은 학습 모델·동적 할당·ROS 2 통신을 가지면 안 되고(지터), 어떤 로봇이 꽂혀도 같은 상위 명령으로 돌아야 한다(HAL).

## 2. 설계 원칙

- **지능은 위 두 층에, 안전은 실시간 계층의 규칙에, 번역은 HAL에.** 실시간 계층은 위에 무엇이 꽂혔는지 모른다.
- **정지는 규칙만 결정한다.** 학습 모델은 제안(청크, 감속 조언)만 하고, 상태 감시기가 물리 기준(관절·속도·작업 영역·추종 오차·접촉력·HAL 폴트)으로만 정지를 결정한다.
- **접합은 진행도로.** 새 청크는 실측 상태를 청크에 투영한 점부터 재생한다. 두 경로의 단순 가중 평균은 금지한다(유효 액션의 평균은 유효하지 않다).
- **공백은 사다리로.** 페이싱 → 로컬 연속 정책 → 규칙 외삽 → 유지 → 정지 → 복귀. 각 단에 상한이 있고, 전이는 모두 로그에 트리거와 함께 남는다.

## 3. 계층 구조

```
[AI 추론 계층]        GPU/원격, 수 Hz~수십 Hz, 어떤 모델이든 (ACT급 ~ VLA)
      │  공통 메시지 규격 + 공유 프레임 버퍼
[로컬 감독 계층]      제어 PC 일반 코어, 30~100Hz, 켜고 끌 수 있는 블록
      │  연속 정책(flow matching) · 감속 조언기 · 작은 눈(용접선 검출) · 공정 상태 추론기
      │  같은 메시지 규격
[실시간 제어 계층]    격리 CCX, 1kHz, 모델 없음, 동적 할당 없음, ROS 2 없음
      │  HAL read → 검증 → 진행도 접합 → 페이싱 → 명령 생성 → 상태 감시기 → HAL write → 계측
[HAL 계층]            함수 포인터 5개 + 공통 데이터 구조. 백엔드: MuJoCo 락스텝 / ros2_control 플러그인
```

### 3.1 자원 분리 (실측)

Threadripper PRO 3955WX, Ubuntu 24.04, PREEMPT_RT 6.8.1-realtime. CCX 단위 코어 격리 `isolcpus=managed_irq,domain,4-7,20-23 nohz_full rcu_nocbs irqaffinity=0-3,8-19,24-31`, governor performance, SCHED_FIFO 99, mlockall, `clock_nanosleep(TIMER_ABSTIME)`. 1kHz 루프는 CPU 4, 시뮬레이터는 CPU 12, 눈·로컬 블록은 8~11, AI 공급자는 14~15, 학습·증강은 0~3,16~19. 격리 코어는 RT 루프 외에 아무것도 올리지 않는다.

| 구성 | 유휴 max | 부하 max | 100μs 초과 |
|---|---|---|---|
| 일반 커널, 격리 없음 (cyclictest) | 592μs | 1325μs (주기 상실) | 19~25/32 코어 |
| RT + CCX 격리 (cyclictest, CPU4) | 76μs | 20μs | 0 |
| **실제 1kHz 제어 루프** (pace_control) | **16.7μs** | **41.8μs** | 0 |

### 3.2 공통 메시지 규격 (`pace/include/pace/msg.h`, 8272B 고정)

헤더: 종류 · 생성 시각 · 유효기간 · 신뢰도 · 시퀀스 · 공급자 ID(AI / LOCAL / EYE / RULE / TEACH / OPERATOR / CONTROL) · 공간(JOINT/TOOL) · 자유도 · 점 수.

| 종류 | 내용 | 쓰임 |
|---|---|---|
| PATH | 시간 매개화 경로 p(t), K점 | 기존 VLA/ACT 청크 호환 |
| PATH_S | 진행도 매개화 경로 p(s), 명목 진행 속도 | 진행도 접합의 공식 형식 |
| CORRECTION | 기준 경로 대비 (가로, 높이, 각도) 보정 | 산업 용접 센서/비전 보정 |
| PARAM | 속도 배율, 공정 파라미터 벡터 | 속도 지령, 아크 출력 |
| EVENT | 끝 / 중단 / 재개 / 결함 / 비상정지 | 비주기 |
| CONTRACT (역방향) | 버퍼 여유, 다음 마감, 지연 분위수, 진행도, 속도 | 제어기 → 상위 (양방향 시간 계약의 자리) |

계층 간 전송은 락프리 공유메모리 `/pace`(SPSC 링 4개 + seqlock 상태·계약 + 프레임 버퍼). 실시간 루프 안에 락·할당·시스템콜이 없다.

### 3.3 실시간 제어 계층 (매 틱)

1. 틱 대기 → 깨어남 지연 기록
2. HAL read (관절 상태·툴 자세·접촉력·폴트 비트·타임스탬프), 실제 소요를 선언 WCET 와 비교
3. 큐 폴링 + **3단계 검증**: 범위(HAL 한계값) → 시간(유효기간·순서·너무 오래된 t0) → 유효성(실측 대비 이탈도, 공급자별 신뢰도 문턱)
4. **진행도 접합**: 타임스탬프로 예상 인덱스를 잡고 그 창에서 실측 q 에 가장 가까운 점부터 재생(단조, NO_OVERLAP 시 거부). 접합 시 명령 불연속은 오프셋으로 두고 감쇠(블렌딩)
5. **페이싱**: 속도 배율 = min(버퍼 여유 기반, PARAM, 감속 조언, 감시기 상한). 남은 참조가 "다음 청크 예상 도착 + 여유" 보다 짧으면 미리 느려진다
6. 명령 생성: 속도·가속도 한계로 변화율 제한 (정지·복귀 램프에만 관절 속도 캡)
7. **상태 감시기**: 실측 + 룩어헤드(50ms)로 관절·속도·작업 영역·추종 오차·접촉력·HAL 폴트 → OK / SLOW / STOP. 히스테리시스(안전한 쪽은 즉시, 덜 안전한 쪽은 20틱 유지). 정지의 유일한 결정자
8. HAL write (정지 3단계 의미: DECEL 램프 명령 / HOLD 위치 잠금 / ESTOP 브레이크 체결)
9. 계측 레코드(128B, 단계별 소요·모드·판정·트리거·정지 단계·아크·접촉력) → 락프리 링

### 3.4 공백 처리 사다리

```
① 늦을 조짐 (버퍼 여유 < 임계)   → 페이싱으로 속도 감소          [느려짐, 멈추지 않음]
② AI 청크 낡음                   → 로컬 연속 정책의 청크 사용     [이어 그림, local_max 까지]
③ 로컬 청크도 없음               → 규칙 외삽 (마지막 속도), 400ms·0.05rad 상한
④ 상태 감시기 트리거             → 저크 제한 감속 → 위치 유지 → 2s 지속 시 비상 정지 (아크 OFF 즉시)
⑤ 유효 청크 복귀                 → 실측 위치에서 접합, 블렌딩으로 재개
```

### 3.5 로컬 감독 계층 (켜고 끌 수 있는 블록)

| 블록 | 입력 | 출력 | 상태 |
|---|---|---|---|
| 작은 눈 (고전 CV) | 토치 근접 카메라 | CORRECTION (가로 오프셋·각도·신뢰도) | 완료, 잔차 0.36mm |
| 연속 정책 (flow matching, 1.19M · 회귀 MLP 1.04M) | 최근 300ms 관절 이력 | PATH 청크 supplier=LOCAL | 완료, 300ms 오차 1.9mrad |
| 보조 궤적 생성기 온라인 학습 (선택) | 검증 통과 후 실제로 실행된 AI 구간 (계약의 실행 상태로 선별) | 배포 체크포인트 (챔피언/도전자 게이트) | 구현·실시간 영향 없음 확인, 폐루프 이득 미확정 (benchmarks 14단계) |

| 공정 상태 추론기 (규칙) | 계약(속도 배율) | PARAM 아크 출력, EVENT DEFECT | 완료 (규칙 기반 대리 모델) |

### 3.6 HAL

```c
struct pace_hal { init, shutdown, read(state), write(tick, mode, q, qd), stop(tick, level), limits(), backend_lag_ticks() };
```

공통 데이터 구조: 자유도·능력 선언(위치/속도/토크)·고유 주기·read/write WCET 계약·관절 한계·속도·가속도·저크·토크·작업 영역. 상태: 관절·툴 자세·접촉력·폴트 비트(드라이브/통신/ESTOP 체결)·타임스탬프. 정지 3단계의 의미는 백엔드가 구현한다.

백엔드: ① MuJoCo 락스텝(공유메모리, futex) ② ros2_control `hardware_interface` 어댑터(ResourceManager 로 플러그인 적재, URDF `<limit>` → 공통 한계값, position+velocity 명령) + 자체 플러그인(`pace_mujoco_hardware`) + mock 플러그인. controller_manager 는 쓰지 않는다(1kHz 루프는 우리 프로세스).

## 5. 시연 시나리오와 결과

### ① 비전 기반 목표 위치 보정 (용접선 추종)

교시 경로는 고정구 오차만큼 실제 용접선에서 틀어져 있다. 작은 눈이 토치 카메라에서 용접선을 검출해 CORRECTION 을 보내고, 제어기가 툴 공간 목표에 더해 IK 로 추종한다.

| 에피소드 | 교시 경로만 | 눈 보정 | 눈 4s 끊김 |
|---|---|---|---|
| ep1 직선 (고정구 오차 0.9~2.0mm) | 1.47mm | **0.29mm** | 0.30mm, 정지 0회 |
| ep5 원호 (−9~+6mm) | 5.05mm | 1.27mm (수렴 후 0.6) | – |

### ② 지연·중단 조건별 동작 (접합 정책 비교)

| 지연 0 / 200ms / 단절 6s | – | 오차 mean 0.25 / 0.25 / 0.27mm, 정지 0회 |

| + 로컬 연속 정책 3s 상한 | 5s | 5s |
| + 로컬 연속 정책(flow matching) 10s 상한 | ≥10s | 약 6s (8s 에서 2.1mm) |
| + 로컬 연속 정책(회귀 MLP) 10s 상한 | ≥10s | ≥10s (10s 에서 0.59mm) |

절제 실험(같은 사다리·같은 청크 구성, 로컬 블록만 교체, 재현 확인): 생성 모델이라서 더 버티는 것이 아니다. flow matching 도 로컬 재생 중에는 1 mm 안이지만 손목 회전·높이로 드리프트하고, 큰 오차는 AI 복귀 접합의 과도 응답이다(점프 비례 블렌딩으로 15.7 → 2.3 mm). 회귀 MLP 는 드리프트가 작아 10 s 에서도 0.6 mm. 킥은 로컬 모델의 종류가 아니라 진행도 접합과 사다리이고, 로컬 블록은 교체 가능한 부품이다.

### ⑥ 접촉력 기반 속도·경로 조정

용접선 위 9mm 돌출부. 토치 끝 접촉 센서 → 2N 초과 SLOW(0.5×), 30N 초과 STOP, 접촉 중 스탠드오프 +12mm. 결과: 접촉력 최대 53N, SLOW 3.1s, STOP 38ms, 상승 +26mm, 완주, 오차 mean 0.40mm.

### ⑦ 공정 상태 추론 기반 파라미터 변경 (규칙)

입열 지수 H = 아크출력/속도. 페이싱으로 0.2× 로 느려지는 구간에서 아크 출력을 30% 까지 낮춰 H 최대 1.7 유지(제어 없으면 5.0). 속도 0.15 미만 2s 지속 시 EVENT DEFECT.

### ⑧ AI 연산 부하 변화에 따른 제어 성능

| 조건 | 깨어남 p99 / max | 실행 p99 / max | AI 추론 p50 / max |
|---|---|---|---|
| 공급자 없음 | 7 / 12.3μs | 6 / 18.1μs | – |
| GT 청크 공급 | 7 / 12.4 | 7 / 15.6 | – |
| GT 청크 + 비격리 코어 stress | 11 / 29.5 | 2 / 12.1 | – |
| 실제 모델 GPU 추론 | 7 / 13.1 | 7 / 16.7 | 6.4 / 7.4ms |
| 실제 모델 CPU 추론 | 7 / 10.3 | 7 / 17.0 | 14.8 / 485.9ms |
| 실제 모델 GPU + stress | 10 / 96.0 | 8 / 49.4 | 7.0 / 9.3ms |

AI 부하는 격리 코어의 루프에 깨어남 지연 수십 μs 로만 전달된다. CPU 추론은 추론 자체가 485ms 까지 늘어져 "공급 지연"이 되며, 그것이 페이싱·사다리가 다루는 영역이다.

### ⑨ 측정 항목 요약

제어주기·지터(깨어남 지연 분포), 단계별 WCET(검증 max 1.7μs, 감시기 0.5μs, IK 15μs), E2E 지연(청크 생성→첫 반영, p50 101~123ms at 지연 100±50ms), AI 추론 시간·주기, 거부율과 사유, 추종 오차(실제 용접선 대비 가로), 저크 p99, 정지·페이싱·로컬·외삽 틱, HAL read/write 계약 위반, 접촉력, 아크 출력.

## 6. 실제 AI 모델 연결 (10단계) — 정직한 보고

ACT급 경량 모델(6.4M, 카메라 2개 + 관절 + 300ms 이력 → 1s 청크)을 GT 데이터로 학습해 실제 공급자로 연결했다. **통합은 성공**했다: 청크 수락 100%(래퍼 평활 후), GPU 추론 6.4ms, 추론 중에도 루프 지터 불변. **모델은 폐루프에서 발산**했다: 보류 에피소드 검증 300ms 오차 3.6mrad 로 로컬 정책과 비슷하지만, 손목 회전에 카메라가 붙어 있어 작은 회전 오차가 영상을 바꾸고 다시 회전을 키우는 자기 피드백이 생긴다. 흔들린 자세에서 GT 로 복귀하는 증강(69k 프레임 재렌더)으로도 해결하지 못했다.

이 결과는 플랫폼의 주장을 오히려 뒷받침한다. 모델이 잡음 청크를 내면 검증기가 거부했고(RANGE_ACC 40건), 발산해 관절 한계에 닿자 감시기가 정지시켰다. 다음 처방: 청크를 툴 공간(x,y,z,진행각)으로 내고 손목 회전은 운동학이 정하게 하기, DAgger 식 폐루프 데이터 수집, CVAE/확산 정책.

## 7. 설계에서 배운 것 (수치가 바꾼 결정)

- 시간 인덱스 재생은 페이싱이 불가능하다(교착). 유효성 검증은 재생 시각 기준이어야 한다.
- 두 경로의 평균은 금지하고 오프셋 감쇠로 접합한다. 접합 시 관절별 속도 캡은 경로를 뒤튼다(정지·복귀 램프에만).
- BLIND 정지는 "마지막 청크 이후 시간" 이 아니라 "참조(외삽 포함)가 바닥난 뒤 시간" 이어야 사다리와 일관된다. 작업 시작 전 대기는 비상정지 카운트 대상이 아니다.
- 눈은 '툴 기준 잔차' 가 아니라 'FK 로 잰 적용 오프셋 + 잔차' 의 절대량을 보내야 한다. 빠른 가로 이동 중 영상 측정은 틀어지므로 운동 게이트·변화율 제한·점프 제한이 셋 다 필요하다.
- HOLD 는 진입 순간 위치를 잠가야 한다(매 틱 갱신하면 서보 강성 0). 정지 중엔 목표를 동결한다.
- ros2_control 은 read() ERROR 에 컴포넌트를 영구 비활성화한다. 플러그인은 position+velocity 명령을 둘 다 노출해야 피드포워드가 산다.
- 오프라인 예측 오차가 낮은 모델이 폐루프에서 더 버티지 않는다(flow matching vs 회귀 MLP). 로컬 블록은 반드시 폐루프 공백 스윕으로 고른다.
- 학습 모델 출력은 점 단위 잡음이 있어 검증기에 걸린다. 1s 지평 용접 동작은 매끈하므로 3차 다항 평활이 맞다. 정책의 신뢰 구간은 짧아(300ms) 새 청크가 올 때마다 재접합한다.
- "멈추지 않는 한계" 와 "허용 오차 안에서 버티는 한계" 를 구분해 보고한다. `local_max_ns` 가 그 사이의 운영 선택이다.

## 8. 한계와 향후 과제

- 실제 AI 모델의 폐루프 안정성 (6절).
- 핵심 수치가 에피소드 0·1 중심. 스윕 도구는 준비되어 있으므로 에피소드 10개 평균으로 확장할 것.
- 감속 조언기는 관절 이력만으로는 무효. 영상·용접선 문맥이 필요.
- GPU 추론 + 비격리 코어 stress 조합에서 깨어남 max 96μs 꼬리. GPU 드라이버 인터럽트 친화성 점검.
- DLS IK 가 빠른 가로 이동에서 자세를 1~2° 늦게 수렴. 눈의 초기 수렴은 리드인 구간에서 먼저.
- 실 로봇 적용: EtherCAT 백엔드(같은 HAL 인터페이스), F/T 센서 또는 드라이브 전류 추정치를 `tool_force` 자리에, 드라이브 정지 카테고리(STO/SS1/SS2)를 정지 3단계에 매핑.
- 2단계 디벨롭: 양방향 시간 계약(CONTRACT 활용), 신뢰도 캘리브레이션, 증명 가능한 안전 코어, AI 공급자 상태 머신.
