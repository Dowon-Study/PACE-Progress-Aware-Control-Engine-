## 2. 같은 질문에 대한 세 답 (비교 가능한 축만)

### 2.1 실시간 제어 주기와 AI 부하

| 축 | PACE 본선 | new_idea |
|---|---|---|
| 루프 지터 (AI 없음) | 깨어남 max 12~17 μs, 실행 max 18 μs | period_error p99 1.5 / max 6.3 μs, lateness max 15 μs |
| 실제 AI GPU 추론 중 | 깨어남 max 13 μs, 실행 p99 7 μs (추론 6.4 ms) | period_error max 4.3 μs (추론 0.7 ms) |
| 비격리 코어 부하 | 깨어남 max 29.5 μs (stress-ng) / 96 μs (GPU 추론 + stress) | period_error max 18.4 μs (matmul 6 스레드), AI 추론은 13 → 52 ms 로 늘어 VALID_HOLD 745 tick |
| 해석 | AI 부하는 격리 코어 루프에 수십 μs 만 전달. 공급 지연은 페이싱·사다리가 흡수 | 같은 결론. 부하는 "AI 쪽 지연"에 나타나고 제어기는 VALID_HOLD 로 응답 |

두 트랙이 독립적으로 같은 결론에 도달했다: **자원 분리가 되면 AI 부하는 제어 주기가 아니라 공급 지연의 문제가 되고, 그 지연을 다루는 것은 승인·백업 논리다.** (RL 트랙은 비실시간 프로세스라 이 축에서 비교 불가.)

### 2.2 AI 중단(outage) 시 동작

| | PACE 본선 (6축 용접) | new_idea (1축) | reforcment_learning (2자유도 접촉) |
|---|---|---|---|
| 기본 동작 | 페이싱(0.2×) → 로컬 청크 → 외삽 → 유지 → 정지 | VALID_HOLD → BACKUP → HOLD → REJOIN | 규칙 감속(0.3×) + 진행 거리 재정합 (math_comp) |
| 정지 없이 버틴 길이 | 2s(유지) → 4s(페이싱+외삽) → ≥10s(로컬 정책) | 2–4s 단절에서 BACKUP 1회, 최종 오차 5.0 mm, 위반 0 | outage 에서 math_comp 는 0.66s 느려지는 대가로 힘 RMSE 0.655 N 유지 |
| 학습 모델의 기여 | 로컬 정책이 4s → 10s 로 늘림. 단, 회귀 MLP ≥ flow matching (절제 실험) | 학습 모델은 보정 공급자일 뿐, 중단 처리에 관여 안 함 (설계상 배제) | **가설 불지지**: GRU 잔차는 outage 에서 감속하지 않아 힘 RMSE 1.03 N 으로 math_comp(0.655)보다 나쁨, ood 에서 STOP 유발 |

세 트랙을 겹쳐 보면 일관된 그림이 나온다. **중단 처리의 핵심은 규칙(페이싱·재정합·백업)이고, 학습 모델은 그 위의 선택적 부품이다.** PACE 의 절제 실험(회귀 MLP 가 flow matching 보다 안정)과 RL 트랙의 결론(math_comp ≥ 학습 잔차)은 서로를 지지한다.

### 2.3 AI 명령 승인 (검증)

| | PACE 본선 | new_idea |
|---|---|---|
| 검사 | 범위 → 시간(유효기간·순서·너무 오래된 t0) → 유효성(이탈도·신뢰도), 거부 11종 | 거부 23종 + 조기 도착 슬롯 + **상태·시간 조건부 허가**(TTL 이 남아도 현재 상태에서 계속 실행·백업 불가면 불허) + **PARAM 백업 가능성 검사**(한계 강화가 현재 상태를 불가능하게 만들면 거부) |
| 실측 | 장애 주입 7종 전부 거부, 실제 모델 잡음 청크 40건 거부 | 22 시나리오 × 5 비교군 행렬: 한계 근접 적대 외란에서 G1(timeout) 431,342 서브스텝 위반 vs G3~G5 위반 0, PARAM 강화 오적용(93 mm) 을 G5 만 거부 |
| 빈 곳 | "이 청크를 실행하면 복구 가능한가" 를 묻지 않는다(한계·이탈도만). 거부 뒤 AI 에게 실행 피드백을 주지 않는다(CONTRACT 에 기록만) | 1축·자유공간·이중 적분기에서만 성립. 다관절·용접에는 미적용 |

new_idea 가 PACE 에 없는 것을 둘 가지고 있다: **복구 가능성(S_rec) 기준 승인**과 **실행 피드백**(거부·개입 뒤 AI 의 자기 믿음 오류 29.4 mm → 4.4 mm). PACE 는 new_idea 에 없는 것을 가지고 있다: 다관절 툴 공간, 진행도 접합, 로컬 연속 정책, 두 로봇 HAL, 공정(아크·접촉) 연동.

## 3. 본선에 가져올 것 (우선순위)

1. **상태·시간 조건부 승인 (new_idea → PACE 검증기 4단계).** 지금 검증기는 "한계 안인가·이탈도 안인가" 만 본다. 청크 끝에서 현재 속도·가속 한계로 정지 가능한지(복구 가능성)를 함께 검사하면 "맞는 청크지만 지금 실행하면 못 멈추는" 경우를 거부할 수 있다. 1축 S_rec 의 다관절 근사는 관절별 정지 거리 상자로 충분하다.
2. **PARAM 백업 가능성 검사.** 공정 상태 추론기가 속도·아크를 바꿀 때, 그 값이 현재 상태와 정지 사다리를 불가능하게 만들지 않는지 검사한다. new_idea 의 G5 가 보여준 것.
3. **실행 피드백 강화.** CONTRACT 에 "실제로 실행한 명령·거부 사유·개입 여부" 를 실어 AI 공급자에게 돌려준다. new_idea 에서 29.4 → 4.4 mm.
4. **학습 잔차 정책은 보류.** RL 트랙과 PACE 절제가 같은 결론이다. 로컬 블록은 단순 회귀를 기본값으로 두고, 생성·강화학습 모델은 폐루프 스윕으로 이길 때만 채택한다.
5. **독립 교차검증 습관.** new_idea 의 C++ 결과를 Python 으로 재계산해 unsound 0 을 확인한 방식을 PACE 감시기 룩어헤드·접합에도 적용한다.

## 4. 한 줄 요약

세 트랙은 서로 다른 플랜트와 방법으로 같은 결론을 냈다. **AI 와 제어를 분리하면 부하는 지연이 되고, 지연·중단은 규칙(승인·재정합·백업·사다리)이 다루며, 학습 모델은 그 위의 교체 가능한 부품이다.** 본선 PACE 는 다관절 용접에서 이것을 실측했고, new_idea 는 1축에서 승인 논리를 증명 가능한 형태로 밀었으며, RL 트랙은 학습 잔차가 규칙을 이기지 못함을 보였다.
