# 확정 아이디어 (2026-10-09 픽스)

> 제안서(PACE)의 핵심인 "경로는 AI, 진행은 제어기"를 유지하면서, 대화를 통해 빈칸을 채운 최종 설계.
> 설계서·코드·벤치마크는 이 문서를 기준으로 한다. 변경 시 이 문서를 먼저 고친다.

## 1. 한 문장

**AI가 느리든, 끊기든, 틀리든 로봇은 물리적으로 멈춰야 할 때만 멈춘다.**
그 사이 제어기는 AI의 경로를 "시간"이 아니라 "로봇이 실제로 어디까지 왔는가(진행도)"를 기준으로 이어 붙이고,
청크가 늦을 조짐이면 미리 느려지고, 끊기면 로컬 모델이 선을 이어 그리며, 정지는 로봇 상태를 보는 규칙만이 결정한다.

## 2. 과제 요구와의 대응

| 과제 요구 (원문) | 이 설계의 답 |
|---|---|
| 3계층 분리, 태스크 우선순위·자원 분리 | 4계층(AI / 로컬 감독 / 실시간 제어 / HAL), PREEMPT_RT + CCX 단위 코어 격리 (실측 완료) |
| 반영 시점과 유효기간을 관리하는 동기화 구조 | 공통 메시지 규격(타임스탬프·유효기간·신뢰도·시퀀스·종류) + 진행도 기반 접합 |
| 값의 범위·유효성·시간 검증 | 3단계 검증기 (입구) |
| 지연·중단 시 급격·불안정 동작 방지 | 페이싱 → 로컬 연속 정책 → 상태 감시기(물리 기준) → 저크 제한 정지 |
| 제어값 변환 (위치·속도·힘·공정) | 메시지 종류 PATH / PATH_S / CORRECTION / PARAM / EVENT |
| 제조사 비종속 HAL | ros2_control hardware_interface 호환, 자체 MuJoCo 백엔드 2종, 공통 데이터 구조(한계값·타임스탬프·정지 3단계·RT 계약) |
| 실측값 제시 | 지터·WCET·E2E·추론시간·통신지연·추종오차·저크·거부율·반응시간 |

## 3. 계층 구조

```
[AI 추론 계층]        원격 또는 GPU 코어, 수 Hz~수십 Hz, 어떤 모델이든 (ACT급 소형 ~ π0급 VLA)
      │  메시지 규격 + 공유 프레임 버퍼
[로컬 감독 계층]      제어 PC 일반 코어, 30~60Hz, 켜고 끌 수 있는 블록
      │  연속 정책(flow matching) / 감속 조언기 / 작은 눈(용접선 검출)
      │  같은 메시지 규격
[실시간 제어 계층]    격리 CCX, 1kHz, 모델 없음, 동적 할당 없음
      │  참조 선택 → 검증 → 진행도 접합 → 페이싱 → 명령 생성 → 상태 감시기
[HAL 계층]            ros2_control 호환 플러그인, 로봇 A/B (MuJoCo), EtherCAT 확장
```

원칙: 지능은 위 두 층에, 안전은 실시간 계층의 규칙에, 번역은 HAL에. 실시간 계층은 위에 무엇이 꽂혔는지 모른다.

## 4. 메시지 규격 (모든 계층 간 공통)

```
헤더: 종류, 생성 시각, 유효기간, 신뢰도, 시퀀스 번호, 공급자 ID
종류:
  PATH         시간 매개화 툴 끝 경로  p(t), K점          ← 기존 VLA/ACT 호환
  PATH_S       진행도 매개화 툴 끝 경로 p(s), s∈[s0,s1]  ← 확정 아이디어의 공식 형식 (방향 1)
  CORRECTION   기준 경로 대비 (가로, 높이, 각도) 보정 흐름 ← 산업 용접 센서/비전 보정과 동일
  PARAM        속도 배율, 공정 파라미터 벡터                ← 속도 지령, 용융풀 적응제어 확장
  EVENT        끝 / 중단 / 재개 / 결함                      ← 비주기
역방향 (제어기 → 상위): 시간 계약 (버퍼 여유, 다음 마감, 실측 지연 분위수) ← 방향 2, 2단계
```

기준 경로는 교시/CAD 경로를 기본으로 두고(산업 관습), AI는 보정·파라미터·세그먼트를 얹는다. VLA가 PATH를 계속 줘도 같은 규격으로 수용한다.

## 5. 실시간 제어 계층 (1kHz, 매 틱)

1. 틱 대기 (clock_nanosleep 절대시각) → 깨어남 지연 기록
2. HAL read → 관절 상태 + 타임스탬프 (상태 이력 링버퍼에 보관)
3. 참조 선택: AI 청크가 신선하면 AI, 낡았으면 로컬 연속 정책, 둘 다 없으면 규칙 외삽 → 유지
4. 3단계 검증: 범위(HAL 한계값) → 시간(유효기간·순서) → 유효성(이탈도·신뢰도, 공급자별 문턱)
5. 진행도 접합: 실측 상태를 새 경로에 투영 → 접합점 (PATH_S면 s 구간 겹침 확인으로 축소) → 재적합 블렌딩 (B-스플라인 최소제곱 또는 Ruckig 재겨냥, **단순 평균 금지**)
6. 페이싱: 속도 배율 = min(버퍼 여유 기반, PARAM 지령, 감속 조언기 제안, 상태 감시기 상한)
7. 명령 생성: 진행 속도 적용, 저크 제한, 역기구학
8. 상태 감시기: 실측 + 룩어헤드(수십 ms)로 관절·속도·가속도 한계, 선 이탈도, 작업 영역, HAL 폴트 → OK / 감속 / 정지. **정지의 유일한 결정자. 규칙만.**
9. HAL write
10. 계측 기록 (락프리 링버퍼)

## 6. 공백(청크 부재) 처리 사다리

```
① 늦을 조짐 (버퍼 여유 < 임계)   → 페이싱으로 속도 감소          [느려짐, 멈추지 않음]
② AI 청크 낡음                   → 로컬 연속 정책의 청크 사용     [이어 그림, 수백 ms~]
③ 로컬 청크도 없음               → 규칙 외삽 (등곡률), 거리·시간 상한 [짧게]
④ 상태 감시기 트리거             → 저크 제한 감속 → 위치 유지 → 안전 정지 (용접: 아크 오프)
⑤ 유효 청크 복귀                 → 실측 위치에서 접합, 차이 비례 블렌딩으로 재개
```

목표 수치: **공백 T까지 정지 0회.** T가 플랫폼의 성능 지표. 정지한 경우 모두 감시기 로그에 물리적 트리거가 남아야 한다.

## 7. 로컬 감독 계층 (블록)

| 구성요소 | 입력 | 출력 | 정답(시뮬 자동) | 비고 |
|---|---|---|---|---|
| 연속 정책 (flow matching, 10~30M, 3~5스텝) | 현재 이미지 + AI 청크 남은 부분 + 관절 상태 + 진행도 | 400~600ms 툴 끝 경로 + 신뢰도 | 용접선 기준 경로 구간 | AI 종류와 무관하게 "이어 그리기"만 학습 |
| 감속 조언기 | 같은 입력 | 속도 상한 제안 0~1 (PARAM) | "이대로 300ms 더 가면 이탈 > ε" | 조언만. 정지 결정권 없음 |
| 작은 눈 (고전 CV 용접선 검출, 1단계) | 툴 근접 카메라 | 오프셋·각도·곡률·신뢰도 (CORRECTION) | 불필요 | 레이저 추적 센서로 교체 가능 (HAL 센서 백엔드) |

학습 모델은 모두 이 층에만 있고, 출력은 전부 실시간 계층의 검증기(입구)와 상태 감시기(출구)를 통과한다. 틀려도 되는 자리에만 모델을 둔다.

## 8. 자원 분리 (실측 완료)

- Ubuntu 24.04 + PREEMPT_RT 6.8.1-realtime, CCX1(CPU 4-7, 20-23) 격리, IRQ는 CCX0, governor performance
- 지터: 일반 커널 유휴 592 / 부하 1325 μs → RT+CCX 유휴 76 / 부하(CPU24+VM+GPU) 20 μs
- 두 PC 구성(AI PC ↔ 제어 PC)은 공유메모리 → UDP/DDS 교체 + PTP 시계 동기화로 동일 구조 지원

## 9. 비교 실험 (벤치마크 설계)

| 축 | 조건 | 기준선 (문헌 근거) | 지표 |
|---|---|---|---|
| 접합 정책 | 지연 주입 0/50/100/200/300ms | 홀드(NCS hold-input), 시간 인덱스(궤적 추적), Ruckig 재겨냥(OTG) vs **진행도 접합** | 추종 오차, 최대 저크, 거부율, 반응 시간(TTFA) |
| 청크 형식 | PATH vs PATH_S | 시간 청크 | 접합 오차, 투영 연산 시간 |
| 공백 처리 | 공백 0~2초 | 홀드, 규칙 외삽, **로컬 연속 정책** | 정지 0회 한계 T, 이탈, 복귀 저크 |
| 격리 단계 | 격리 없음 / RT / RT+CCX | - | 지터 분포 |
| AI 부하 | 없음 / stress / 실제 추론 | - | 지터, E2E |
| 장애 주입 | 지연·중단·이상값·단절·AI kill | - | 사다리 전이 타임라인, 감시기 트리거 로그 |
| 블록 유무 | 로컬 감독 계층 on/off | - | T 변화 |

## 10. 2단계 디벨롭 (1단계 완성 후)

- 양방향 시간 계약 (제어기 → AI: 버퍼 여유·마감·지연 분위수; AI 래퍼: 스텝 수·지평선 조절)
- 신뢰도 캘리브레이션 (신뢰도 vs 실측 이탈 보정 곡선 → 문턱·연장 상한을 데이터로 결정)
- 증명 가능한 안전 코어 (정지 거리 ≤ 남은 여유 조건을 폐형식으로, 수십 줄 격리 커널)
- AI 공급자 상태 머신 (정상/불안정/사망 → 참조 우선순위, 재시작 요청)
- 장애 시나리오 세트를 재현 가능한 벤치마크로 공개
- 용융풀 적응제어 확장: 감속 조언기 슬롯에 공정 상태 예측기 (PARAM 채널)

## 11. 하지 않기로 한 것

- 실시간 루프 안의 학습 모델, ROS 2 통신, 동적 할당
- 픽셀 월드 모델 (검증 불가, 비용 과다; 기하 예측으로 충분)
- 두 경로의 단순 가중 평균 블렌딩 (유효 액션의 평균은 유효하지 않음)
- 학습 모델의 단독 정지 결정
- controller_manager 안에서 1kHz 루프 실행, mujoco_ros2_control 전제(시뮬·제어 동일 프로세스) 사용

## 12. 구현 순서 (1단계)

1. 메시지 규격 헤더 (PATH, PATH_S, CORRECTION, PARAM, EVENT) + 상태 구조체
2. 락프리 공유메모리 (청크 큐, 상태 버퍼, 프레임 버퍼, 계측 링버퍼)
3. 1kHz 루프 뼈대 + 자체 MuJoCo 백엔드 (별도 프로세스, 1ms 락스텝) → "진짜 루프" 지터·WCET 측정
4. 가짜 공급자 (스크립트 경로) + 3단계 검증기 + 상태 감시기
5. 진행도 접합 (PATH, PATH_S) + 비교용 정책 3종 + 재적합 블렌딩
6. 페이싱 + 규칙 외삽 + 사다리 + 장애 주입기 → 공백 T 측정
7. 작은 눈(고전 CV) + 기준 경로 + CORRECTION 흐름 → 시나리오 ① 시연
8. HAL 정식화 (hardware_interface 플러그인), 로봇 B → 시나리오 ④
9. 로컬 감독 계층 블록: 연속 정책 + 감속 조언기 (학습) → T 증가 확인
10. 실제 AI 모델 연결 (ACT급), 보조 실험 (gym-aloha/ACT, 가능하면 LIBERO/π0)
11. 측정·시각화 도구, 비교 실험 자동화, 설계서

## 13. 관련 연구 위치 (설계서 관련 연구 절 초안)

- 부품의 선례: 경로 추종/MPCC(투영), 시간 스케일링(페이싱), 패킷화 예측 제어(청크 버퍼), OTG/Ruckig(블렌딩), OOSM(타임스탬프 재정합), 지연 보상 MPC(미래 겨냥), 서보 보간(명령 생성)
- 최신 모델 측 해법(위층 옵션으로 수용): RTC, VLASH, Training-time RTC, PAINT, FutureRTC, ABPolicy, DEHP, FASTER
- 최신 제어기 측 해법(가장 가까운 비교): VLPSA(공간 안전, 직교), FluxVLA Engine(stitching, 실시간성 측정 없음), AEGIS/LIBERO-Safety(청크 단위 CBF)
- 빈 자리: 청크 부재·외란·1kHz 실시간 보장·실측을 한 플랫폼에서 다룬 연구 없음 → 이 설계의 기여
